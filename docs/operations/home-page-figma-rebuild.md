# Главная витрины пересобрана по макету (MKT-SCR-001)

12.09.2026. Основание: владелец открыл витрину на поднятом стеке и сказал,
что это не макет. Проверка подтвердила: страница была собрана не по
утверждённому фрейму.

## Чем подтверждается расхождение

Утверждённый фрейм — `Home page` v4 long (`3428:55239`, 1920x5544), решение
зафиксировано в [marketplace-screen-build-spec](../discovery/marketplace-screen-build-spec.md),
строка MKT-SCR-001. Структура фрейма читается из локальной копии файла
Figma (`analysis_tools/fig_data.bin`, распакованный kiwi) скриптом
`analysis_tools/dump_frame_tree.js`, тексты — `dump_texts.js`.

Снимок страницы до работы — 1920x2418 против 1920x5544 у макета.

| Секция фрейма | Было |
| --- | --- |
| `3851:56175` hero: логотип 557x180, слоган «ЛУЧШИЙ СПОСОБ НАЙТИ НЕДВИЖИМОСТЬ» 50px, фотополотно 1920x596 | белый блок, форма поиска и свой текст «Поиск недвижимости в Грузии» |
| `3428:55271` пять категорий с фотографиями и счётчиками, ширины 390/470/410/450/450 | пять одинаковых плашек с мелкой иконкой, без счётчиков |
| `3428:55292` «Почему выбирают BAZA.sale?» + три довода | свои тексты про комиссию и проверку |
| `3428:55382` промо: блок продажи 670x500 + «Горячие предложения» SALE до 30% | две мелкие карточки |
| `3428:55605` «Горячие предложения»: 4 карточки ЖК 424x626 | отсутствовала |
| `3428:55845` «Новые объявления квартир»: 4 карточки 424x663 | отсутствовала |
| `3428:56071` «Каталог проверенных риелторов» | отсутствовала |
| `3428:56103` «Рейтинг застройщиков» | отсутствовала |

То есть на главной не было ни одного объекта недвижимости, хотя две
секции с объектами занимают в макете 1529px из 5544px.

## Что сделано

`HomePage.tsx` пересобран посекционно в порядке фрейма. Тексты и кегли
взяты из узлов макета (`3851:56182` слоган 50px, `3428:55296` заголовок
50px, `3428:55609` заголовок рельсы 28px, `3428:55611` «Смотреть все» 22px,
`3428:55602` SALE 131px, `3428:55604` «до 30%» 60px). `home.css` переписан
от размеров фрейма: контейнер 1760, карточка 424, пропорции промо 670/1040,
фотополотно 1920:596.

Данные настоящие: «Горячие предложения» — `GET /public/developments`,
«Новые объявления квартир» — `GET /public/listings?dealType=sale`,
счётчики категорий — поле `total` тех же ответов, без отдельных запросов.
При отказе API секции показывают пустое состояние с причиной, а не
подставные карточки.

Плейсхолдер обложки (`.building-placeholder`) заменён: вместо цветных
«башен», которые читались как элемент дизайна, спокойный силуэт дома.
Маска иконки объявлена токеном `--placeholder-house` в `tokens.css`
URL-кодированной: незакодированные `<` и `>` внутри `url()` ломают разбор
значения, и маска молча не применяется.

## Второй заход 12.09: картинки и геометрия из самого файла

Первая версия была собрана по перечню блоков: размеры секций и тексты, а
отступы, радиусы, тени и начертания додуманы. Владелец увидел расхождение
сразу. Причина в инструменте: `dump_frame_tree.js` показывал только тип,
имя, размер и текст узла.

Теперь из файла читается всё, что нужно для вёрстки.

**`analysis_tools/dump_spec.js`** — автолэйаут узла (направление, интервал,
внутренние поля, выравнивание), кегль и начертание, межстрочный, трекинг,
цвет, радиусы, обводки, тени. Тексты инстансов берутся из мастер-символов
(`symbolData.symbolID`), поэтому нашлись пилюля «Преимущества», кнопка
«+ Разместить объявление», кнопки карточек «Позвонить» и «Написать»,
бейдж «Premium».

**`analysis_tools/extract_images.js`** — растровые картинки. Оригинал
`Batumi Real Estate Project.fig` (177 МБ) нашёлся в загрузках владельца;
это ZIP, внутри `images/<sha1>`, и тот же sha1 лежит в `fillPaints[].image.hash`
узла. Так фотография из макета связывается со своим прямоугольником.
Извлечённое пережато под веб (hero 1920px, плитки категорий по 760–820px,
JPEG 82) и лежит в `apps/marketplace-web/public/figma/`.

**`analysis_tools/vector_to_svg.js`** — векторные иллюстрации. Геометрия
лежит не в узле, а в блобе: `fillGeometry[].commandsBlob` — индекс в
`msg.blobs`, формат — байт команды и следом пары float32
(0x00 close, 0x01 move, 0x02 line, 0x03 quad, 0x04 cubic). Учитывается
полная матрица трансформации, узлы-маски пропускаются (иначе выезжают
чёрными прямоугольниками), рамка при необходимости считается по
фактическим границам (у мастер-символов дети лежат в координатах
страницы). Так собраны три иллюстрации преимуществ, значок-пламя у
заголовков рельс и баннер «SALE» целиком: дом с лупой, карточки риэлторов
со звёздами, зелёная диагональ.

Текстовая группа баннера (`3428:55598`) из экспорта исключена: тексты
живут в разметке, иначе подложка макета садится поверх настоящего текста.

Заодно удалены правила старой главной из `app.css` и `figma-surface.css`
(177 строк): они переопределяли новую вёрстку, рисовали белую карточку
вокруг hero и на широком экране раскладывали hero в две колонки.

## Чего в этой работе нет

- **Секции риэлторов и застройщиков не собраны.** Публичного API для них
  не существует: `/public/*` — это `developments`, `listings` и
  `selections`. Нарисовать их можно только на выдуманных людях, что
  запрещено тем же правилом, по которому 11.09 вычищали засев community.
  Нужен backend: публичный список организаций с числом объектов и
  профили риэлторов (последнее пересекается с N-13, отзывы).
- **У публичной карточки ЖК нет фотографий.** `PublicDevelopmentCard` —
  это slug, имя, локация, класс, срок сдачи, цена и состав квартир; поля
  media нет вовсе, хотя в макете обложка карточки ЖК это фотография.
  Отдельный пробел проекции публикации.
- **Фотографии объектов.** Иллюстрации самого макета теперь на месте, но
  обложки карточек по-прежнему пустые: в тестовой базе фотографий нет ни у
  одного объекта, а у публичной карточки ЖК поля media нет вовсе.
- **Лицензия на стоковые фотографии** из макета — вопрос к владельцу и
  автору макета: файлы пришли из `.fig`, их происхождение здесь не
  проверялось.
- **Visual compare владельцем не проведён.** Экран остаётся `scaffold` до
  вердикта в [figma-visual-compare-checklist](../discovery/figma-visual-compare-checklist.md).

## Расхождение внутри самого макета

Фрейм главной заканчивается тёмным `footer 3` (`3428:56129`, #262626), а
единым футером для всех экранов владелец утвердил светлый `footer 1`
(`3067:73634`), см. MKT-SCR-003. Реализация оставлена на `footer 1`;
какой из двух правильный на главной, должен сказать владелец.

В текстах макета есть опечатки и следы прежнего проекта: «Коммеция»,
«Новые обьявления квартир», «разместите свое объявление на DREAM». В коде
написано «Коммерция», «Новые объявления квартир» и «на BAZA».

## Третий заход 12.09: шапка, подвал, категории

Владелец показал живую страницу и прямо перечислил, что плохо: картинки
категорий на чёрном фоне и обрезанный ряд, в шапке текст вместо логотипа и
непонятная точка у «Войти», наведение в подвале. Разрешил отступать от
макета там, где это делает красивее.

- **Категории.** Чёрный фон — моя ошибка: PNG с прозрачностью пережат в
  JPEG, и прозрачное стало чёрным. Иллюстрации заменены на присланные
  владельцем 3D-картинки в WebP с прозрачностью. Ряд больше не выходит за
  край: пять плиток в сетке с долями ширин из макета.
- **Шапка** собрана заново (`Header.tsx`, классы `bz-header*`, файл
  `chrome.css`). Прежняя жила на четырёх наборах правил, которые
  перебивали друг друга, а общее правило `button { … } button:hover {
  translateY }` из app.css красило и подбрасывало каждую её кнопку. По
  компоненту `299:4629`: знак логотипа из макета и «BAZA», семь разделов с
  подчёркиванием активного, «+ Разместить» белой пилюлей, «Войти» контурной
  пилюлей со значком-ключом в квадрате, язык, валюта, булавка с городом.
  Колокольчик уведомлений не выводится: уведомлений в продукте нет.
  Разделы видны до 1240px, ниже уходят в бургер.
- **Подвал** (`Footer.tsx`, `bz-footer*`): колонки выровнены по левому
  краю, наведение — только цвет и тонкое подчёркивание; значки соцсетей
  больше не раздуваются.
- **Кнопка «Позвонить»** — фирменный зелёный вместо фиолетового `#7065f0`
  из макета, по просьбе владельца. Вторая кнопка карточки ЖК — «Подробнее»
  (писать продавцу с витрины пока некуда), быстрый просмотр планировок
  переехал пилюлей на обложку. Карточки кликабельны целиком.
- **Обложки без фото** показывают 3D-иллюстрацию раздела на мягком фоне
  вместо пустой плиты.
- **Мобильная**: нижнее меню прилипает к низу экрана, третий пункт —
  сердце «Избранное» вместо шестерёнки из макета, которой не на что
  вести. Исправлено горизонтальное переполнение на 375px (длинная ссылка
  подвала не переносилась).

Заодно починен runtime-гейт: Docker Hub перестал отдавать образы MinIO,
сначала `minio/mc`, затем и `minio/minio`. Оба compose-файла берут сервер
из официального реестра `quay.io/minio/minio`, а инициализация хранилища
идёт на том же образе, в котором `mc` уже есть.
