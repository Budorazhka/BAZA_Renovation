# Расписание протухания актуальности

## Что сделано

`ActualityService.expireOverdueListings` снимает просроченные listing'и с
публикации, `apps/api/src/jobs/actuality-expire.command.ts` даёт ей точку входа
вне HTTP, `pnpm --filter api run actuality:expire-overdue` её вызывает. Не
хватало последнего звена: **эту точку входа никто не вызывал ни в одном
окружении**, поэтому объявления не протухали никогда, ни локально, ни в
runtime-стеке.

Добавлен сервис `actuality-expire` в `infrastructure/compose/compose.runtime.yml`
под профилем `scheduled`.

```bash
docker compose -f infrastructure/compose/compose.runtime.yml --profile scheduled up -d
```

Интервал задаётся переменной `ACTUALITY_EXPIRE_INTERVAL_SECONDS` (по умолчанию
3600 секунд).

## Почему так

**Профиль, а не сервис по умолчанию.** Прогон E2E не должен получать фоновых
мутаций данных под собой: сценарий публикует объект и проверяет его в каталоге,
а параллельный процесс в это время меняет статусы публикаций. По умолчанию
сервис не поднимается — включается осознанно.

**Цикл на `sh`, а не `@nestjs/schedule` и не cron-образ.** В кодовой базе нет ни
одной scheduling-зависимости (обоснование — в докстринге
`actuality-expire.command.ts` и `apps/worker/src/jobs/media-cleanup.command.ts`).
Здесь добавляется расписание, а не новый паттерн в коде: сама команда осталась
нетронутой, решение «когда вызывать» по-прежнему живёт в инфраструктуре.

**`|| true` в цикле намеренно.** Команда выходит с кодом 1, когда часть
listing'ов не обработалась (`result.errors > 0`). Это повод для записи в лог, а
не для остановки расписания: иначе один битый listing выключил бы протухание
для всех остальных до ручного вмешательства.

## Для собственного сервера (без compose)

Если API разворачивается не через compose, расписание задаётся обычным
crontab-ом рядом с приложением, сервис из compose не нужен:

```cron
0 * * * * cd /srv/baza-platform && pnpm --filter api run actuality:expire-overdue >> /var/log/baza/actuality-expire.log 2>&1
```

## Что осталось открытым

- **Интервал не согласован с владельцем.** Час взят как разумный дефолт для
  суточных порогов актуальности, не как решение по продукту. Если пороги
  измеряются днями, ежечасный прогон избыточен; если минутами — недостаточен.
- **Нет метрики и алерта.** Провал прогона виден только в логах контейнера.
  Ненулевой `errors` в течение нескольких прогонов подряд означает системную
  проблему (например, недоступный PublicationService), и это должно поднимать
  тревогу, а не копиться в stdout.
- **Единственный экземпляр.** При нескольких репликах команды прогон пойдёт
  параллельно. Сейчас это безопасно (обработка listing'ов идёт по одному, с
  проверкой статуса), но блокировки на уровне расписания нет.

## Поправка от 05.09.2026: erp-web из стека убран

Вместе с расписанием в `compose.runtime.yml` был добавлен сервис `erp-web` и
переменная `CORS_ALLOWED_ORIGIN_ERP`. Сервис оказался неподъёмным и **удалён**.

Причина: `apps/erp-web` намеренно исключён из workspace
(`pnpm-workspace.yaml`) — его зависимостей нет в lockfile, и подключение к
гейтам там прямо названо отдельным решением. Его Dockerfile при этом делает
`pnpm install --frozen-lockfile` и `turbo run build --filter=@baza/erp-web...`,
то есть ровно то, что в таком состоянии работать не может.

Runtime-гейт упал из-за этого дважды подряд: сначала на установке зависимостей
(`ERR_UNKNOWN_BUILTIN_MODULE: node:sqlite` на Node 20), затем на сборке
(`No package found with name '@baza/erp-web' in workspace`). Второе падение
показало, что дело не в версии Node, а в самом исключении из workspace.

Переменная `CORS_ALLOWED_ORIGIN_ERP` оставлена, но по умолчанию пуста: без неё
`resolveProductAudienceFromOrigin` не попадает в ветку `'erp'`, и это честное
состояние стека, в котором ERP-клиента нет. Тот, кто поднимает ERP своими
командами рядом, задаёт переменную своим origin.

Урок на будущее: прежде чем добавлять приложение в runtime-стек, проверить, что
оно вообще входит в workspace. Комментарий «apps/erp-web в этом worktree не
существует» был устаревшим, но вывод из него я сделал неверный — код появился, а
в сборку он по-прежнему не входит.
