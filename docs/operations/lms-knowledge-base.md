# LMS: материалы, курсы и прогресс (этап 11, частично)

Дата: 11.09.2026. Код — `be0e5f7` (10.09), исправления — `802aae2` (10.09),
проверка теста на сервере (11.09).
Статус: работает в пределах организации. Прохождение теста больше не
засчитывается со слов клиента — сервер сам сверяет ответы. Правильные ответы
по-прежнему уходят в ответе на чтение курса (см. «Что открыто» №1) — это не то
же самое, что была защищена дыра: одно про то, что читающий тест ВИДИТ, второе
про то, что читающий тест мог ЗАСЧИТАТЬ, не решая его.

## Что сделано

- Модуль `apps/api/src/modules/lms`, маршруты под `/lms`: `items` и `courses`
  (чтение, создание, правка, удаление), `progress` (чтение, запись и сброс по
  курсу).
- Материалы разных типов (статья, видео, PDF, скрипт, презентация), курсы из
  материалов с итоговым тестом, прогресс по должности.
- Системные материалы и курсы засеваются при старте API в пустые коллекции,
  помечены `isSystem`.
- Все запросы фильтруются по организации. Изоляция подтверждена разбором 10.09.
- ERP: `lmsApi.ts` переведён с моков на API. Пути, `Idempotency-Key` и формат
  `{success, data}` совпадают с контроллером.
- Права — permission-matrix §1.7.

## Исправлено 10.09

- Ошибки сидирования глушились `catch {}`: реальный сбой в проде был неотличим от
  штатного пропуска в юнит-тестах. Теперь пишутся в лог, старт API не роняют.
- Из курса менеджера убран видео-элемент со ссылкой на посторонний ролик вместо
  записи. Настоящего видео-тура по CRM нет.

## Почему так

Мастер-план ставит LMS в этап 11, «после стабилизации основных продаж», с тем же
vertical-slice DoD. Модуль пришёл раньше очереди; изоляция и права сделаны по
конвенциям, проверка знаний — нет.

## Исправлено 11.09: тест проверяется сервером, не клиентом

`PUT /lms/progress/:courseId` принимал `finalQuizPassed`/`finalQuizScore` из
тела запроса и сохранял как есть — `{finalQuizPassed: true}` защитывал курс
пройденным без единого правильного ответа, `LmsCourseCompleted` уходил в
outbox по тому же телу.

- Тело запроса (`UpsertLmsProgressRequest.finalQuizAnswers`) теперь несёт
  только то, что реально выбрал учащийся — индекс варианта на каждый вопрос.
  `LmsService.upsertProgress` читает курс внутри той же транзакции и сам
  сверяет ответы с `finalQuiz.questions[].correct`; `finalQuizPassed`/
  `finalQuizScore` в ответе — только результат этой проверки. Курс без
  финального теста засчитывается прочтением всех `itemIds`; несуществующий
  `courseId` — `NOT_FOUND`, прогресс не пишется (раньше не проверялся вовсе).
- Заодно исправлен и пункт 3 старого списка: `completedAt` ставился только
  `$setOnInsert` — запись прогресса создаётся при первой же отметке
  прочитанного материала, задолго до теста, поэтому дата завершения не
  появлялась почти никогда. Теперь ставится один раз, в момент перехода в
  завершённое состояние; проваленная пересдача не откатывает более раннюю
  дату первого прохождения назад, хотя `finalQuizPassed`/`finalQuizScore`
  при этом отражают именно последнюю попытку.
- ERP: `progress.ts::setFinalQuizResult` отправляет `finalQuizAnswers` вместо
  посчитанных в браузере `passed`/`score`; `QuizViewer` по-прежнему считает их
  локально для мгновенной подсказки в интерфейсе — на то, что реально
  засчитано сервером, это не влияет.
- Проверено на настоящей MongoDB
  (`test/integration/lms-quiz-grading.integration-spec.ts`, 7 тестов):
  верные/неверные ответы, попытка подменить тело запроса старым форматом,
  повторная сдача, отметка материала после сдачи не сбрасывает результат,
  курс без теста, несуществующий курс.

## Что открыто

1. **Правильные ответы всё ещё уходят читающему тест.** `toLmsCourseDto`
   отдаёт `correct` каждому, у кого есть право чтения курсов — по сути всей
   организации. Это не то же самое, что исправлено выше: раньше можно было
   засчитать тест, ВООБЩЕ его не решая (ответы сервера игнорировались);
   теперь для зачёта нужно реально угадать/списать правильные варианты — но
   подсмотреть их в ответе сервера перед прохождением по-прежнему можно.
   Закрыть нельзя без переделки самого прохождения теста: `QuizViewer` (ERP)
   сверяет выбор с `correct` локально, чтобы показать результат сразу, без
   ответа сервера — раздельная выдача (полный список автору курса, вопросы
   без ответов проходящему) требует сначала перевести показ результата на
   ответ сервера. Самостоятельная задача.
2. Мутации без аудита и без `expectedVersion`, списки без лимита.
3. Сид делает upsert без уникального индекса по `itemId`/`courseId`: несколько
   реплик API при одновременном старте могут создать дубли. Системный контент
   курсов написан агентом, владелец его не утверждал.
4. `url` материала на бэкенде не валидируется и попадает в `iframe src` и `href`
   в ERP (`viewers.tsx`). Риск только от своих сотрудников с правом `manage`.
5. ERP (`useLms.ts`) при 401 и 403 молча показывает моки вместо ошибки.
   `lmsApi.ts` называет параметры `targetRole`/`search`, DTO ждёт `role`/`type` —
   пока их никто не передаёт, при передаче будет 400.
6. Загрузка файлов материалов идёт на старый `CRM_API_BASE_URL`.
7. Организации, созданные до 10.09, не имеют грантов LMS, пока в окружении не
   запущена доливка `grants:backfill-defaults` (N-06,
   [default-grants-backfill](default-grants-backfill.md)).
