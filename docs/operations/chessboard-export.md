# chessboard.export — выгрузка шахматки ЖК в XLSX

Статус: implemented (31.08.2026)

## Контекст

`{resource:'chessboard', action:'export', scope:'organization'}` был выдан почти всем ролям
(owner/director/rop/administrator/marketer/developer) в `DEFAULT_ROLE_GRANTS` с самого начала, но до
этого коммита слово `chessboard` встречалось в кодовой базе РОВНО в одном файле — в самой таблице
грантов. Ни эндпоинта, ни сервиса, ни строки в OpenAPI: выгрузки шахматки не существовало, при том
что сами данные (ЖК → корпуса → этажи → юниты со статусом и ценой) давно есть и работают.

Владелец решил (31.08.2026) не изобретать формат, а взять уже существующий из
`bz26-client-erp` (`src/lib/chessboard-xlsx.ts`, `exportUnitsToXlsx`) — чтобы файл открывался и
считался привычным для команды образом и принимался тем же импортёром.

## Формат файла

Лист **`Шахматка`**, одна строка заголовков, дальше строки квартир. Без стилей, объединённых ячеек,
заголовочных блоков, итоговых строк и автофильтра — ровно как в оригинале (там SheetJS Community,
который стили игнорирует в принципе).

15 колонок, символ валюты подставляется в заголовки:

```
Корпус | Этаж | Номер | Комнатность | Площадь, м² | Цена за м², $
      | Цена: Черный каркас, $/м² | Цена: Белый каркас, $/м² | Цена: Зеленый каркас, $/м²
      | Цена: С ремонтом, $/м² | Цена: Под ключ, $/м²
      | Базовая цена за м², $ | Итого, $ | Статус | Акция
```

Статусы: `available → Свободно`, `reserved → Бронь`, `sold → Продано`, `hidden → Снято с продажи`
(у оригинала на месте последнего `withdrawn`; `hidden` в BAZA — модерационный статус вне продажного
цикла, та же семантика «в продаже не участвует»).

Имя файла — паттерн оригинала: `chessboard_<имя ЖК>_<YYYY-MM-DD>.xlsx`.

### Осознанные расхождения с оригиналом

1. **Пять колонок цен по кондициям и «Базовая цена за м²» всегда пустые.** В `UnitDocument` нет ни
   `finishPrices`, ни `basePricePerSqm` — у юнита ровно одна цена. Колонки сохранены (владелец
   подтвердил) ради совместимости формы файла с тем ERP.
2. **«Цена за м²» вычисляется** (цена ÷ площадь, округление до целого), а не читается — BAZA хранит
   только итоговую цену. Округление то же, что `computeUnitTotalPrice` в оригинале, который считает
   обратную величину через `Math.round`.
3. **Строки сортируются** корпус → этаж → номер (номера — numeric-коллацией, иначе «10» встаёт перед
   «2»). Оригинал не сортирует вообще, пишет в порядке прихода из стора: для выгрузки одного корпуса
   это терпимо, для ЖК целиком — нечитаемо.
4. **Выгружаются только `kind:'apartment'`** (владелец, 31.08.2026). Паркинги/кладовые/коммерция
   лежат в той же коллекции; без фильтра любой подсчёт по файлу (средняя цена м², остатки) смешивал
   бы несопоставимые типы.
5. **Суммы конвертируются из minor units** (÷100) — API хранит деньги целочисленно (conventions.md
   разд.1), в выгрузке нужны привычные числа.
6. **Санитайзер имени файла принимает ё/Ё** — в оригинале они выпадали из диапазона `[а-яА-Я]` и
   заменялись подчёркиванием.

## Архитектурные решения

- **`GET /api/v1/developments/:developmentId/chessboard/export`** — единственный эндпоинт API,
  отдающий не JSON. `@Res` без passthrough, тело пишется прямо в `FastifyReply`, `Content-Type` и
  `Content-Disposition` ставятся явно (helmet в `main.api.ts` сконфигурирован в расчёте на JSON-only
  ответы). Кириллическое имя файла отдаётся через `filename*=UTF-8''…` (RFC 5987) с ASCII-фолбэком.
- **ADR-008 («файлы не ходят телом через API») здесь не нарушается по смыслу**: он про
  пользовательские медиа произвольного размера, которые лежат в S3 и отдаются presigned-ссылкой. Тут
  — сгенерированный на лету отчёт в сотни килобайт, живущий ровно один запрос и нигде не хранимый.
- **`exceljs`, а не тот же `xlsx` (SheetJS Community 0.18.5), что в оригинале**: в npm-версии SheetJS
  известны prototype pollution (CVE-2023-30533) и ReDoS, исправленные версии автором в npm не
  публикуются. На результат замена не влияет — файл представляет собой плоскую сетку без стилей.
  Единственная зацепка аудита у `exceljs` — moderate-адвизори в транзитивном `uuid@8.3.2` (нужен
  внешний `buf`-аргумент, которого exceljs не передаёт) — недостижима в этом сценарии.
- **Чистые функции формата вынесены в `chessboard-export.ts`** (колонки, значения строки,
  сортировка, имя файла) и покрыты тестами без всякого workbook-рантайма; `chessboard-workbook.service.ts`
  содержит только запись готовых строк в лист.
- **Потолок `MAX_CHESSBOARD_EXPORT_UNITS = 20 000`** проверяется через `countDocuments` ДО чтения
  юнитов — иначе защита от неограниченного чтения срабатывала бы уже после того, как весь массив
  оказался в памяти процесса. Это не пагинация (файл по определению отдаётся целиком), а
  предохранитель.
- **Смешанные валюты в одном ЖК — явная 400**, а не молчаливая выгрузка: символ валюты в этом формате
  стоит в ЗАГОЛОВКЕ колонки (наследие оригинала, где валюта — свойство проекта целиком), а
  `MoneyAmount` в BAZA хранится по-юнитно, поэтому единый заголовок неизбежно соврал бы про часть
  строк.

## Verification

- API unit: `chessboard-export.spec.ts` (15 тестов — колонки/валютные символы/значения строки/пустые
  finish-колонки/статусы/округление/сортировка/имя файла), `developments.service.spec.ts`
  (`buildChessboardExport`, 7 тестов — резолв корпуса и этажа, kind-фильтр, 404 чужого ЖК до чтения
  юнитов, смешанные валюты, потолок до чтения в память, пустой ЖК, сортировка),
  `unit.repository.spec.ts` (`listForBuildings`/`countForBuildings`, 3 теста — `$in`-фильтр,
  пустой список корпусов не идёт в БД, count тем же фильтром, что чтение).
- Mongo replica-set integration: `chessboard-export.integration-spec.ts` (8 тестов) — реальный
  Fastify, реальные байты, полученный workbook **распаковывается обратно** и сверяется по листу,
  заголовкам и значениям ячеек; плюс kind-фильтр, сортировка по всему ЖК, доступ маркетолога по
  гранту, 404 на чужой ЖК, 401 без сессии, 400 на смешанные валюты, валидный файл для пустого ЖК.
- OpenAPI (`GET /developments/{developmentId}/chessboard/export`, binary-ответ) и
  `packages/api-client/src/schema.ts` синхронизированы (`check-stale` проходит).

## Не сделано намеренно

- **Нет UI.** Это бэкенд-эндпоинт; кнопки «Скачать шахматку» в ERP пока нет.
- **Нет выгрузки паркинга.** Если понадобится — отдельная выгрузка с `kind:'parking'`, а не
  колонка «Тип» в этой (владелец, 31.08.2026).
- **Нет `export.run`.** Второй «мёртвый» грант (выгрузка CRM-списков) остаётся нереализованным —
  это отдельная задача с другими данными.
