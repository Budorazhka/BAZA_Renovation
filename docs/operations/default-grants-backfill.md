# Доливка стартовых грантов в существующие должности (N-06)

Дата: 11.09.2026. Статус: сделано; команда разовая, её нужно запустить в каждом
окружении, где есть организации, созданные до появления новых грантов.

## Что было

Стартовый набор прав роли (`DEFAULT_ROLE_GRANTS`) применялся только при
создании должности. Механизма доливки не было — это записано в
`default-role-grants.ts` ещё с `position.read` (31.08) и в
[media-upload-grant](media-upload-grant.md) (01.09). Каждый новый раздел
означал 403 для всех организаций, созданных раньше: 10.09 так остались без
messenger, LMS и community все организации до этой даты. Тот же разрыв ждал
перенос со старой системы: организация, перенесённая до выхода нового гранта,
не получила бы его никогда.

## Что сделано

- `DefaultGrantsBackfillService` (`apps/api/src/modules/organizations`)
  проходит по должностям всех организаций пачками по курсору `_id` и доливает
  отсутствующие стартовые гранты роли.
- Пара resource+action считается выданной, если по ней есть **любой** грант:
  - активный с другим scope не дополняется вторым — `evaluate()` берёт любое
    совпадение, и `lead.read`, суженный вручную до `own`, стал бы
    организационным;
  - отозванный не возвращается — revoke append-only, это решение человека.
- Закрытые должности (закрытие = удаление) не выбираются. Должности моложе
  10 минут пропускаются: `createOrganizationWithOwner` пишет их гранты после
  коммита транзакции, доливка в это окно дала бы дубли.
- Каждая должность — своя транзакция: гранты перечитываются в снимке,
  недостающие вставляются, в аудит пишется `position.default_grants_backfill`
  от системного актора с организацией, ролью и списком `resource.action:scope`.
  Сбой одной должности не останавливает остальные.
- Чтение грантов пачки идёт через `PolicyEvaluatorService.listGrantKeysForSubjects`:
  граница модулей не пускает organizations в репозиторий authorization.
- Межорганизационная выборка должностей `listNotClosedPage` внесена в
  исключения стража tenant-scope с причиной.

## Как запускать

Сначала без записи — отчёт тот же:

```bash
pnpm --filter @baza/api run grants:backfill-defaults -- --dry-run
pnpm --filter @baza/api run grants:backfill-defaults
```

В образе API:

```bash
docker compose -f infrastructure/compose/compose.runtime.yml run --rm api \
  node apps/api/dist/jobs/grants-backfill.command.js --dry-run
```

Отчёт: сколько должностей просмотрено и дополнено, сколько грантов и каких
(`addedByGrant`), сколько отозванных пар сохранено (`revokedKept`), сколько
свежих пропущено, ошибки. Код выхода 1 при ошибках.

Когда запускать:
- после выкладки релиза, который добавил записи в `DEFAULT_ROLE_GRANTS`;
- после переноса организаций со старой системы (N-03);
- сейчас — в каждом окружении с организациями до 10.09 (messenger, LMS,
  community).

Параллельно с самой собой не запускать: два одновременных прогона могут
долить одну пару дважды. Дубль не меняет результат проверки прав, но засоряет
список грантов.

## Чего доливка не делает

- Не переносит смену scope уже выданной пары и не отзывает гранты, убранные
  из `DEFAULT_ROLE_GRANTS`. Это расширение или сужение прав, отдельное решение.
- Не трогает ⚙-переключатели (`personal_access.grant`) и гранты админ-аккаунтов.

## Проверено

- Юнит-тесты сервиса (8): доливка с аудитом в той же транзакции, суженный scope
  и отозванный грант не трогаются, dry-run не пишет, свежие пропускаются,
  повторное чтение в транзакции не даёт дублей, сбой одной должности, курсор,
  повтор.
- Интеграционный на настоящей MongoDB (`default-grants-backfill.integration-spec.ts`):
  владелец «до 10.09» получает гранты messenger, LMS, community, и
  `evaluate()` их пропускает. Отозванный `lms_course.manage` остаётся
  закрытым, `lead.read` остаётся `own`. Менеджер без грантов получает ровно
  набор роли. Закрытая, свежая и полностью выданная должности не тронуты. Аудит
  — по записи на изменённую должность. Повтор ничего не меняет.
- Живой запуск `ts-node src/jobs/grants-backfill.command.ts` на полном AppModule
  против Mongo в памяти: `--dry-run` насчитал 75 грантов и ничего не записал,
  прогон долил 75 (9 из них community) и одну запись аудита, повтор — 0.

## Что открыто

- **Команду нужно запустить.** Код сам ничего не доливает: в окружениях с
  организациями до 10.09 до запуска остаётся 403 на messenger, LMS и community.
- **Нет блокировки от параллельного запуска** — только правило в этом документе.
- **Нет напоминания в релизном процессе.** Страж, который требовал бы запуска
  после изменения `DEFAULT_ROLE_GRANTS`, не заведён; при появлении деплой-пайплайна
  команду стоит сделать его шагом.
