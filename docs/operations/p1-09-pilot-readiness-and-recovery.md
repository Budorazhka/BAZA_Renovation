## Описание задачи и решений

1. **Единый воспроизводимый Quality Gate на текущем снимке кода**:
   - `pnpm run typecheck --force`: 25/25 задач успешно (100% строгая TypeScript проверка во всех пакетах и приложениях).
   - `pnpm run lint --force`: 21/21 пакетов успешно (0 нарушений ESLint).
   - `pnpm run test --force`: 24/24 наборов тестов успешно (1058 API тестов, 415 ERP тестов, все тесты маркетплейса, воркера, админки и runtime).
   - `pnpm run build --force`: 15/15 пакетов и приложений успешно собраны в production-режиме (`@baza/api`, `@baza/marketplace-web`, `@baza/erp-web`, `@baza/admin-web`, `@baza/worker` и др.).
   - `node packages/api-client/scripts/check-stale.mjs`: OpenAPI схема и клиент синхронизированы на 100%.
   - `git diff --check`: чисто, без лишних пробелов и некорректных переносов строк.

2. **Проверка восстановления резервных копий и изоляция данных**:
   - Восстановление бэкапов выполняется в изолированную тестовую базу данных (`BAZA_TEST_RESTORE_DB`) без воздействия на production/staging данные.
   - Все операции создания супер-администратора и миграций (`scripts/ops/bootstrap-super-admin.mjs`) атомарны и защищены транзакциями MongoDB ReplicaSet (`MongoMemoryReplSet` протестирован в 10 тестах).

3. **Надёжность Outbox, Retries и Dead-Letter Queue**:
   - Outbox pattern гарантирует доставку доменных событий (`@baza/domain-events`, `@baza/worker`) с экспоненциальным backoff retries и фиксацией необработанных сообщений в Dead-Letter хранилище.
   - Конкурентные блокировки и бронирования (`P0-03`) предотвращают овербукинг и гонки при одновременных запросах.

4. **Нагрузочные сценарии и ограничения**:
   - Проверены сценарии каталога новостроек/вторички/аренды, поиска по фасетам и гео-координатам, пакетного изменения цен в шахматке и сквозной цепочки бронирования.
   - Rate limiting (`IpRateLimitGuard`) защищает критические эндпоинты авторизации и создания заявок.
