### Итоговая сводка по секции CRM (детализация для отдельной проверки)

- Kanban-доска лидов (`kanban clients`, `card_lead`) — 3 варианта размера карточек + режим "не редактируется" + настройка размера
- Задачи — список / канбан / матрица Эйзенхауэра, создание задачи (пустая/заполненная/с файлом/с подзадачей), просмотр, все ×desktop+mobile
- Заметки — список / создание / просмотр / удаление (2 варианта удаления — вероятно с подтверждением и без, или разные типы объекта удаления)
- Календарь — неделя / день (2 версии дня)
- Уведомления — отдельный экран + "Новости на весь экран"
- Отчёты по эффективности риэлтора, "Колесо фортуны" (геймификация, ×2 варианта — неожиданная находка, требует уточнения у владельца, относится ли к MVP или это будущая фича)
- "дашборд платформы" — отдельный крупный фрейм, не до конца понятно, это дашборд риэлтора или что-то более общее — `question`

## 3. Явные ошибки/edge-state, найденные в Figma (важно для Definition of Done)

Мастер-план (разд.7.2) требует loading/empty/error/success/forbidden/conflict состояния для каждого сценария. Figma подтверждает наличие некоторых из них дизайнером явно:

- **Error state**: `mob_add object_4_errors` (мастер добавления объекта, мобильный, шаг 4).
- **Disabled/forbidden state**: кнопки управления объектом "на модерации" — задокументировано текстовой заметкой в самой Figma (раздел «Кабинет риелтора»), кнопки мессенджеров "не активны" (раздел «Добавление объекта») до заполнения контактов.
- **Empty/placeholder не найден явно** ни в одной секции — по всем спискам (Мои объекты, CRM-лиды, Задачи, Заметки) заполненное состояние показано, пустое — нет. Это разрыв между Figma и требованием DoD, стоит поднять отдельно как задачу на дозаполнение макетов, а не как блокер discovery.
- **Loading state** — не найден нигде на уровне глубины 3 (возможно, есть внутри какого-то фрейма как скрытый вариант, не проверялось на большей глубине).

## 4. Разделение marketplace vs ERP/Admin — подтверждение

Явного пересечения с ERP/Admin функциональностью в файле не обнаружено. Секция "CRM" внутри Main pages — это marketplace-кабинет риэлтора (личный, для независимого пользователя без организации), а не ERP-CRM агентства/застройщика: в ней нет мультипользовательских/командных сущностей (Position, назначение лида другому менеджеру, воронка организации) — только личные лиды/клиенты/задачи одного риэлтора. Это соответствует Accepted decision "независимый риэлтор может работать самостоятельно" и корректно ограничивает scope Figma только под marketplace, как и требует приоритет источников ТЗ (Figma для marketplace, ERP-репозиторий для ERP-сценариев).

## 5. Компоненты, типографика, цвета, grid/breakpoints (частично подтверждено)

- **Breakpoints**: подтверждены ровно два — desktop 1920px и mobile 375px. Промежуточного tablet-брейкпоинта в файле не обнаружено ни в одном фрейме (все фреймы либо 1920, либо 375 по ширине, кроме компонентов/иконок меньшего размера).
- **Типографика**: по скриншоту панели стилей, предоставленному владельцем — два текстовых семейства с именами стилей `Comf` (Comf 20/18/16/14/12, все с пометкой Auto line-height, кроме Comf14/Comf12 — 14/19 и 12/19) и `Jak` (Jak 28/24/20/18, часть Auto, часть с фиксированным line-height 150/19). Полные font-family (реальные названия шрифтов, не просто "Comf"/"Jak" — вероятно внутренние алиасы) не подтверждены, не выгружены через API из-за 403 на `/styles`.
- **Цвета**: по тому же скриншоту — именованные color styles: `Main color`, `dart text` (вероятно опечатка дизайнера, "dark text"), `light grey`, `FFFFFF`, `light element background`, `element stroke`, `back gradient` ×2, `subheader gradient`, `Error bg`, `Error`, `hover green`. Полные HEX/OKLCH-значения не подтверждены тем же ограничением.
- **Компоненты**: UI kit-страница подтверждает наличие переиспользуемой библиотеки — `left menu` (component set), `filters_mob`, флаги стран (circle/square variants — подтверждает мультистрановую/мультиязычную поддержку на уровне компонентов), обширная иконочная библиотека по категориям (Messages/Arrows/Map/Video/Money/Electronic/Weather/Files/Astronomy/Folders и другие, не все перечислены).
- **Hover/focus/disabled states**: не проверены на уровне отдельных компонентов (потребовало бы разворачивания каждого COMPONENT_SET на дополнительную глубину) — но САМ ФАКТ, что ключевые интерактивные элементы (`small button with icon`, `кнопки управления объектом`, `актуальность`, `статус`) оформлены как `COMPONENT_SET` (а не единичный `COMPONENT`), подтверждает наличие вариантов состояний внутри — какие именно (hover/focus/disabled/active), не выгружено.

## 7. Не удалось проверить / ограничения

- **Полное содержимое каждого экрана** (конкретные текстовые поля, реальные подписи кнопок, точные состояния форм) — выгружена только структура до глубины 3, не листовые узлы внутри каждого экрана.
- **Prototype-переходы** (какая кнопка на какой экран ведёт) — не запрашивались через `GET /v1/files/:key` (prototype-связи не включены в стандартный ответ на этой глубине), для этого нужен отдельный запрос с explicit prototype-параметрами.
- **Полные HEX/значения цветов и точные font-family** — эндпоинт `/styles` вернул 403 (недостаточный scope токена), не переспрашивался повторно у владельца ради этого второстепенного уточнения.
- **hover/focus/active-состояния внутри конкретных компонентов** — не разворачивались на дополнительную глубину.
- **4 версии "Home page"** и **5 вариантов Footer** — Figma не даёт понять, какая версия актуальна, без ручного визуального сравнения самим владельцем или дизайнером.
- **2 фрейма прямо помечены дизайнером "(не используется)"** (`ЖК целая страница`, `Проект целая страница`) — не включены в основной build-scope выше, зафиксированы отдельно.
- **Страница "Рабочий процесс"** (2 "лендинг"-фрейма) не обследована вглубь — не выглядит частью продуктового scope, не приоритетно.
- **Токен использован единожды** для получения структуры на глубину 3 плюс попытка `/styles`; дальнейшие запросы к Figma API в рамках этого обследования не выполнялись, чтобы не расходовать зря ограниченный по времени токен владельца.
