# Чек-лист визуальной сверки с Figma

Рабочий документ для финального прохода владельца. Решение о том, что экран
сделан, принимается здесь, а не в коде и не в реестре.

Реестр экранов, статусы и расхождения по узлам — в
[figma-ui-delivery-gate.md](figma-ui-delivery-gate.md). Этот файл его не
заменяет: он про один шаг — сесть с открытым Figma и сравнить.

## Как пользоваться

1. Открыть снимок из `screenshots/` и фрейм по ID из таблицы рядом.
2. Пройти по колонке «На что смотреть» — там то, в чём я не уверен сам.
3. Поставить вердикт: `совпадает` / `правки` (и какие) / `фрейма нет`.

Вердикт `совпадает` по обоим брейкпоинтам переводит экран из `scaffold` в
`ready for owner review` в реестре. Пока вердикта нет, экран остаётся
`scaffold`, независимо от того, насколько он выглядит готовым.

## Что снимки значат, а что нет

Снимки сделаны в сквозном гейте на поднятом стеке с реальными данными: каталоги
показывают засеянные объекты, кабинет — объект самой сессии. Это не макетные
данные и не заглушки.

Четыре экрана по-прежнему работают на захардкоженных массивах внутри компонентов
и backend за ними нет: рейтинг риэлторов, профиль риэлтора, запросы клиентов,
подборки объектов. Их снимки выглядят наполненными, и это обманчиво — сверять
по ним можно вёрстку, но не поведение.

Мобильные снимки сделаны в 375px. Промежуточного tablet-брейкпоинта в файле
Figma нет, поэтому и в съёмке его нет.

## Вопросы не по экранам

**Два фирменных зелёных.** В токенах живут `--color-accent: #169600` и
`--color-main: #1BA800` — оттенки разные, оба используются как основной. Второго
до 05.09.2026 вообще не существовало: двадцать одно объявление писало
`var(--color-main, #1BA800)` и держалось на fallback, то есть цвет был вписан
хексом в двадцати одном месте. Токен объявлен, значение взято из fallback и с
макетом не сверялось. Нужно решить, какой из двух зелёных настоящий.

**Обещания на главной надо подтвердить.** «0% комиссия», «100% проверка»,
«Бесплатно разместите объявление и найдите покупателей среди тысяч
пользователей», «скидки от застройщиков и партнерские комиссии» — это заявления
от лица компании, а не данные объекта. Взяты из фрейма или дописаны при вёрстке,
я не знаю; убирать их самому нельзя, подтвердить может только владелец.

Отдельно: выдуманные данные объектов из кода убраны 05.09.2026 — цены и
планировки на детальной странице ЖК и плашка «от 32 м²» на карточке показывались
одинаковыми у всех комплексов. Возвращать их можно только из публичной проекции,
когда юниты начнут публиковаться.

**Иконки категорий на главной сделаны эмодзи** (🏢 🔑 🏠 🏬 🏞), хотя в UI kit
`40:4517` есть иконочная библиотека. Эмодзи рисуются по-разному в разных
системах и не имеют состояний. Нужны сами иконки из макета.

## Как пересобрать снимки

Основной способ — сквозной гейт: шаг `Capture marketplace screenshots` в
`.github/workflows/runtime-release-gate.yml` снимает экраны на поднятом стеке и
кладёт артефактом `marketplace-screenshots`.

```bash
gh run download <run-id> --name marketplace-screenshots --dir docs/discovery/screenshots
```

Локально нужен Docker и поднятый runtime-стек:

```bash
pnpm runtime:up
node apps/e2e-runtime/scripts/capture-marketplace-screens.mjs
```

Без стека снимки получаются в состоянии ошибки загрузки и для сверки не годятся.
