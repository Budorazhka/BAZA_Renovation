# Скриншоты marketplace для visual compare

Сняты 05.09.2026 в сквозном гейте, на поднятом runtime-стеке с реальными
данными: шаг `Capture marketplace screenshots` в
`.github/workflows/runtime-release-gate.yml`, скрипт
`apps/e2e-runtime/scripts/capture-marketplace-screens.mjs`. 17 экранов в двух
брейкпоинтах Figma (desktop 1920 и mobile 375), полностраничные, масштаб 1:1.
Машинный отчёт прогона — `capture-report.json`.

Чек-лист сверки, по строке на экран, — в
[../figma-visual-compare-checklist.md](../figma-visual-compare-checklist.md).

## Что эти снимки значат, а что нет

**Снимок это половина сверки.** Вторая половина, сопоставление с фреймом Figma,
делается человеком. Наличие файла в этой папке не переводит экран в
`ready for owner review`.

**Данные настоящие.** Каталоги показывают объекты, засеянные сквозными
сценариями; детальные страницы адресуются slug'ом опубликованного объекта;
кабинет и страница редактирования сняты под сессией, у которой есть свой
объект. Предыдущая версия этих снимков делалась без backend и показывала
состояния ошибки загрузки — по ней сверять было нечего.

**Три экрана кабинета сняты формой входа, а не содержимым.** `MKT-SCR-019`
(мои объекты), `MKT-SCR-020` (мастер публикации) и `MKT-SCR-021` (редактирование
объявления) закрыты `RequireAuth`, а вход в браузере на этом прогоне не
завершился: форма приняла запрос, но сессия не установилась. Аккаунт и его
объект при этом заводятся исправно — адрес страницы редактирования в отчёте
собран с настоящими идентификаторами. Разбирается: съёмка научена называть
причину отказа и ждать лимит входов, следующий прогон покажет её точно. По этим
трём экранам сверять пока нечего.

**Четыре экрана работают на захардкоженных массивах** внутри самих компонентов:
рейтинг риэлторов, профиль риэлтора, запросы клиентов, подборки объектов
(`MOCK_REALTORS`, `MOCK_REVIEWS`, `INITIAL_REQUESTS`, `INITIAL_COLLECTIONS`).
Backend за ними нет, у подборок он есть, но страница к нему не подключена. Их
снимки выглядят наполненными, и это обманчиво: сверять по ним можно вёрстку, но
не поведение.

## Как пересобрать

```bash
gh run download <run-id> --name marketplace-screenshots --dir docs/discovery/screenshots
```

Локально нужен Docker и поднятый стек:

```bash
pnpm runtime:up
node apps/e2e-runtime/scripts/capture-marketplace-screens.mjs
```

Без стека снимки получаются в состоянии ошибки загрузки и для сверки не годятся.
