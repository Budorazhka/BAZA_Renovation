# Скриншоты marketplace для visual compare

Сняты 04.09.2026 скриптом
`apps/e2e-runtime/scripts/capture-marketplace-screens.mjs` против собранного
`marketplace-web` (`vite build` + `vite preview` на порту 4173). 28 снимков:
14 экранов в двух брейкпоинтах Figma, desktop 1920 и mobile 375. Полностраничные,
масштаб 1:1. Машинный отчёт прогона — `capture-report.json`.

Это первые скриншоты по гейту вообще: до этого дня пункт DoD «Screenshot
implementation сопоставлен с Figma» не был закрыт ни по одному из 21 экрана.

## Что эти снимки значат, а что нет

**Снимок это половина сверки.** Вторая половина, сопоставление с фреймом Figma,
делается человеком. Наличие файла в этой папке не переводит экран в
`ready for owner review`.

**API не поднят.** Backend в момент съёмки не работал, поэтому четыре экрана на
реальных данных (`MKT-SCR-004`, `005`, `010`, `011`) сняты в состоянии ошибки
загрузки: в `capture-report.json` у них зафиксированы 404 на запросы каталога.
Это честное текущее состояние, но сверять по ним сетку карточек нельзя. Чтобы
получить снимки с данными, поднимите runtime-стек
(`infrastructure/compose/compose.runtime.yml`) и запустите скрипт заново.

**Девять экранов работают на фикстурах.** `MKT-SCR-014`…`019`, `022`, `023`,
`024` рисуют захардкоженные массивы в самих компонентах (`INITIAL_LEADS`,
`INITIAL_TASKS`, `INITIAL_EVENTS`, `INITIAL_FAVORITES`, `INITIAL_PROPERTIES`,
`INITIAL_REQUESTS`, `INITIAL_COLLECTIONS`, `MOCK_REVIEWS`). Их снимки выглядят
наполненными, но за ними нет backend. При сверке это надо держать в голове:
красивый снимок здесь не означает работающий экран.

## Замечания по итогам первого просмотра

Полноценную сверку с фреймами должен провести человек, у которого открыт Figma.
Ниже то, что видно уже по снимкам и что стоит проверить в первую очередь.

### Иконки взяты эмодзи, а не из UI kit

На `MKT-SCR-004` категории отрисованы эмодзи (🏢 🔑 🏠 🏬 🏞), на `MKT-SCR-022`
эмодзи стоят в табах (📊, ✓, 🗓) и в метке города (📍). При этом
`figma-screen-inventory.md` §5 фиксирует на Canvas `40:4517` обширную иконочную
библиотеку по категориям (Messages, Arrows, Map & Location, Money, Files и
другие). Замена библиотеки эмодзи — расхождение с Figma, а не стилевая мелочь:
эмодзи рендерятся по-разному в разных ОС и не имеют состояний.

### Нечитаемые элементы на `MKT-SCR-004`

- Активная вкладка поиска над полем ввода отрисована как пустая зелёная плашка:
  текст на ней не виден.
- В состоянии ошибки каталога кнопка повторной попытки выводит зелёный текст на
  зелёном фоне и не читается.

И то и другое — дефекты контраста, их видно на снимке без всякой Figma.

### Сообщение об ошибке не про тот объект

При недоступном каталоге экран пишет «Объект не найден или больше не
опубликован». Это текст про одну карточку, а не про список, который не
загрузился. Пользователь получает утверждение о судьбе объекта вместо сообщения
о сбое связи.

### Главная и каталог слиты в одном маршруте

`/` рендерит и hero с поиском, и категории, и промо-блоки, и список ЖК. В Figma
это разные фреймы: `Home page` (`3428:55239`, 1920x5544) и `search result`
(`236:27197`, 1920x1216). Нужно решение: разделять на два маршрута или оставить.

### Композиционные приёмы, требующие подтверждения по фреймам

- Мелкий uppercase-надзаголовок над hero («✦ ПРОВЕРЕННАЯ НЕДВИЖИМОСТЬ В ГРУЗИИ»).
- Заголовок hero целиком в верхнем регистре.
- Плитки метрик «крупное число + мелкая подпись» на `MKT-SCR-022`.
- Карточки внутри карточек в колонках канбана.

Каждый пункт может оказаться точным переносом фрейма, а может быть привычным
шаблоном исполнителя. Отличить одно от другого можно только открыв фрейм.

## Как пересобрать

```bash
pnpm --filter @baza/marketplace-web build
cd apps/marketplace-web && npx vite preview --port 4173 --strictPort
# в другом терминале
cd apps/e2e-runtime && node scripts/capture-marketplace-screens.mjs
```
