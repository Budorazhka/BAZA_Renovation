# BAZA.sale — Figma-only UI Delivery Gate

Статус: **обязательно для каждого marketplace UI-изменения с 26.08.2026**.

## Зачем это нужно

Marketplace переписывается по Figma. Цель этого документа — не допустить generic-интерфейсов, переносов визуального мусора со старого сайта и «логичных» дизайнерских догадок исполнителя.

Визуальная правда marketplace: Figma.  
Поведение, не отражённое в Figma: решение владельца и принятые продуктовые документы.  
Старый сайт: только инвентарь функций и SEO, не образец UI.

## Обязательная последовательность

### 1. До кода

Для конкретного route исполнитель создаёт запись в таблице ниже и заполняет все поля:

1. Figma URL и точный node ID конкретного фрейма.
2. Имя фрейма, его desktop/mobile-варианты и интерактивные состояния.
3. Список компонентных вариантов, которые реально используются на экране.
4. Привязку к файлам реализации.
5. Явные Figma gaps: отсутствующие loading/empty/error/forbidden/conflict-состояния, спорные варианты, `(не используется)`.

Без этой записи UI-код не начинается.

### 2. Во время реализации

- Снимать размеры, сетку, отступы, typography, цвета, радиусы, границы и hover/focus/disabled из Figma или Figma component/variable styles.
- Реализовывать только подтверждённые блоки и взаимодействия.
- Не переносить HTML/CSS/визуальный паттерн со старого `baza.sale`.
- Не создавать "улучшающий" hero, выдуманные карточки, декоративные иллюстрации, fake stock imagery, фейковые метрики или несуществующие фильтры.
- Не применять Hallmark, шаблонные UI-подходы или произвольную новую палитру как замену Figma. Они допустимы только для технической реализации уже подтверждённого Figma-решения и не могут менять композицию.
- Если данных API не хватает для Figma-блока, зафиксировать backend gap; не скрывать его placeholder-данными и не менять дизайн под ограничение API без решения владельца.

### 3. Перед сдачей

1. Снять screenshot реализации в размерах соответствующего Figma-фрейма.
2. Сверить визуально с Figma: layout, header/footer, сетка, размеры карточки, цвета, шрифты, states, mobile.
3. Записать результат сверки и известные backend/Figma gaps в таблицу.
4. Проверить минимум desktop и Figma mobile-вариант. Если mobile в Figma отсутствует — явно отметить это.
5. Только после этого статус может стать `ready for owner review`.

## Definition of Done для marketplace UI

- [ ] Есть точный Figma node ID и ссылка.
- [ ] Подтверждены используемые desktop/mobile-фреймы.
- [ ] Нет выдуманной визуальной структуры или дизайна.
- [ ] Все подтверждённые Figma states реализованы.
- [ ] Отсутствующие в Figma states отмечены как gap и согласованы/следуют принятому DoD.
- [ ] Screenshot implementation сопоставлен с Figma.
- [ ] Функциональные API-gaps вынесены отдельным списком, а не замаскированы.
- [ ] Typecheck/test/build пройдены.

## Формат отчёта исполнителя

Вместо фразы «сделал страницу» вернуть только:

1. Figma refs: URL + node IDs.
2. Реализованные файлы.
3. Что совпало с Figma.
4. Какие states/детали отсутствуют в Figma и как они были согласованы.
5. Screenshot paths и результат visual compare.
6. Backend gaps, которые мешают точному переносу.
