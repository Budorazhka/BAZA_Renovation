# Marketplace Gap Matrix — обследование живого сайта baza.sale

Дата обследования: 2026-08-25. **Обновлено 25.08.2026 после получения доступа к Figma** — колонка «Figma эквивалент» ниже была заполнена как `TBD` на момент первого прохода (Figma была недоступна без токена); теперь сверена с `docs/discovery/figma-screen-inventory.md`.
Метод: WebFetch (рендер контента без полного выполнения JS) + прямые HTTP-запросы (curl) для проверки raw HTML `<head>`, HTTP-заголовков и публичных API-эндпоинтов (`api.baza.sale`). Без авторизации, без bulk-скрейпинга (единичные точечные запросы для верификации находок технического аудита).

**Важно:** данные ниже расходятся местами с `Технический_аудит_baza.sale.txt` (аудит датирован 21.07.2026, источник данных — API-выгрузка того дня). За месяц сайт частично пропатчен. Каждая находка ниже помечена как **подтверждена / исправлена / не проверена** относительно старого аудита, где применимо. Старый аудит не дублируется — используется как база для сравнения.

Стек живого сайта (обнаружено по `<meta name="generator">` и структуре HTML): публичные страницы каталога — **Astro v5.18.0** (SSR/SSG); авторизованная зона под префиксом `/app/*` — гидратируемый JS-остров (вероятно React, наследник старого `berega-client`), отдаёт малый HTML-shell (~5.6 КБ) с общим тайтлом — **полный контент недоступен без выполнения JS**.

| `[unverified — ...]` | Явное признание, что утверждение не подтверждено напрямую (обычно из-за CSR/JS-ограничения WebFetch) |

## Технические SEO-находки (сводно)

- **Title/description дублируются на всех проверенных detail-страницах карточек объявлений (`/secondary/{id}`) и профилей риэлторов (`/realtors/{id}`)** — оба типа страниц отдают тот же `<title>` и `<meta description>`, что и главная. Это classic duplicate-content: поисковик видит тысячи страниц с одинаковым title. Canonical при этом выставлен корректно (указывает на себя, не на главную) — то есть noindex-эффекта от canonical не будет, но релевантность в выдаче по duplicate title/description снижена.
- **Title на detail-странице комплекса (`/newconstructions/{id}`) уникален**, но содержит нетранслированный технический слаг города (`batumi` вместо "Батуми") — паттерн "частично исправлено, но с новым багом".
- **JSON-LD структурированные данные не обнаружены ни на одном проверенном типе страницы** (главная, каталоги, карточка объекта, карточка ЖК, профиль риэлтора, журнал). Для недвижимости ожидались бы `RealEstateListing`/`Product`/`Offer`/`BreadcrumbList`/`Person` (для риэлторов) — отсутствуют полностью, что означает отсутствие rich snippets в поисковой выдаче.
- **hreflang (ru/en/ka/x-default) присутствует** на проверенных Astro-страницах (главная, карточка вторички) — это плюс, отсутствовавший в апдейте аудита (аудит эту тему не поднимал).
- **robots.txt** не покрывает фактическую структуру приватных разделов (`/app/*`), правило `Disallow: /admin/` не соответствует реальному пути `/app/admin`.
- **`[live verified: https://baza.sale/sitemap.xml, дата 25.08.2026, метод curl, статус 200]` sitemap.xml содержит 6908 URL** (пересчитано точным методом `grep -o '<loc>' | wc -l`, исправляет ошибочное «1019» из более ранней версии этого документа — см. подробный разбор в основной таблице выше). Покрытие по сущностям: вторичка (3264 из 10084 в API, ~32%) и аренда (3543 карточек) индексируются существенно; новостройки почти не индексируются (30 из 5269 комплексов, <1%); **риэлторы не индексируются вовсе** (0 из 177+ реальных профилей, при том что SSR detail-страницы с корректным canonical реально существуют). Разрыв индексации локализован в новостройках и риэлторах, не является общим пробелом по всему каталогу.
- **Хлебные крошки (breadcrumb navigation)** не обнаружены ни на одной проверенной странице через WebFetch — не удалось подтвердить их отсутствие окончательно, так как WebFetch дает ограниченный DOM.
