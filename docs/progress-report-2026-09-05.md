## 1. Коротко

Период занят двумя вещами: **UI маркетплейса по Figma** и **правдивостью того,
что показывается наружу**. Второе не планировалось — оно вылезло из первого.

Как только экраны начали снимать на поднятом стеке, нашлось три вещи, которые
до этого никто не видел, потому что смотреть было не на что:

- **на публичных страницах показывались выдуманные данные объектов** — цены и
  планировки, одинаковые у каждого ЖК;
- **в кабинет нельзя было войти вообще** — `GET /auth/session` отказывал при
  штатной топологии фронта;
- два дефекта контраста и несуществующий токен цвета.

Ни одно из этого не находилось тестами. Все три нашлись снимком экрана.

## 3. Что сделано

### 3.1. Figma UI Delivery Gate

Заведён [гейт](discovery/figma-ui-delivery-gate.md): реестр из 21 экрана, у
каждого — узлы Figma, файл реализации и статус. Правило простое: **без ID узла
код не пишется, ненарисованное не выдумывается, экран не сдан без сверки со
снимком.**

Первым же применением гейт поймал собственную подделку: предыдущий исполнитель
проставил 21 экрану статус «проверено в коде», не открыв ни одного фрейма и не
сняв ни одного снимка. Статусы понижены до `scaffold`, и **все 24 строки реестра
в нём и остались** — ни один экран не подтверждён.

Что построено по гейту: главная отделена от каталога (решение владельца по
образцу действующего `baza.sale`), разделы `/newconstructions`, `/secondary`,
`/rent`, самостоятельные страницы входа и регистрации, страница «не найдено»,
редактирование объявления, избранное с настоящим backend.

### 3.2. Съёмка экранов в CI

Шаг `Capture marketplace screenshots` сквозного гейта снимает 17 экранов в двух
брейкпоинтах на поднятом стеке с реальными данными и кладёт артефактом. До этого
по гейту не было снято ни одного снимка, то есть пункт DoD «сопоставлен с Figma»
нельзя было закрыть ни по одному экрану даже теоретически.

Материал для владельца — [чек-лист сверки](discovery/figma-visual-compare-checklist.md):
строка на экран, ID фреймов, файлы снимков и то, в чём исполнитель не уверен сам.

### 3.3. Убраны выдуманные данные с публичных страниц

На детальной странице **любого** ЖК показывались четыре квартиры с площадями и
ценами и блок «Стоимость квартир: от $39 000, от $1 200 / м², возможна
беспроцентная рассрочка». На карточке в каталоге — плашка «от 32 м²». Всё это
было вписано в код и одинаково у всех объектов, включая обещание рассрочки,
которого застройщик не давал.

Данных нет по объективной причине: публикация юнитов не реализована — воркер
помечает каждое событие с `sourceType: 'unit'` как `build_failed`. Страница
теперь говорит, что планировки появятся после публикации, а блок цены не
выводится.

### 3.4. Войти в кабинет было нельзя

Браузер не шлёт заголовок `Origin` на same-origin GET. Фронт по умолчанию ходит
в API через свой же прокси (`VITE_API_BASE_URL=/api/v1`). Результат:
`POST /auth/login` проходил и ставил cookie, а следующий `GET /auth/session`
падал с `AUTH_AUDIENCE_MISMATCH`; клиент читал отказ как «гость» и уводил на
форму входа.

Ни один сценарий этого не ловил: сессию проверял только логаут, а он ходит через
клиент, который `Origin` проставляет всегда. Добавлен сценарий
`06-cabinet-session` — вход формой, кабинет и новая загрузка страницы.

### 3.5. Прочее

- **OpenAPI-долг закрыт полностью**: 49 недокументированных маршрутов → 0,
  реестр пробелов у стража пуст.
- Правка объявления из маркетплейса пишется в журнал версий (`listing_updated`).
- Регистрация в сквозных сценариях была скопирована в четыре места, ожидание
  лимита — в одном; сведена в общий помощник.
- Два дефекта контраста (бейдж сделки, вкладка поиска) и токен `--color-main`,
  которого не существовало: 21 объявление держалось на fallback.

## 4. Разрывы и риски

### 4.1. Ни один экран не сверен с Figma

24 строки реестра в статусе `scaffold`. Материал готов, сверка не проведена —
это единственное, что отделяет UI от сдачи, и делать её должен человек с
открытым Figma.

Открытые вопросы, на которые нужен ответ владельца, собраны в чек-листе: два
разных фирменных зелёных в токенах (`#169600` и `#1BA800`); иконки категорий
сделаны эмодзи вместо библиотеки из UI kit; заявления на главной («0% комиссия»,
«100% проверка», «среди тысяч пользователей»), которые подтвердить может только
владелец.

### 4.2. Четыре страницы рисуют захардкоженные массивы

Рейтинг риэлторов, профиль риэлтора, запросы клиентов, подборки объектов. У
подборок backend есть — страница к нему просто не подключена; у остальных трёх
backend нет вовсе. Снимки этих экранов выглядят наполненными, и это обманчиво.

### 4.3. Юниты не публикуются

Воркер помечает каждое событие с `sourceType: 'unit'` как `build_failed`. Из-за
этого у ЖК нет ни планировок, ни цен, а модалка быстрого просмотра юнита
недостижима и не снимается.

### 4.4. Журнал версий маркетплейса пишется, но не читается

Ревизии правок пишутся, эндпоинта для чтения нет — есть только организационный.
Запись включена раньше чтения намеренно: история копится со дня включения,
задним числом её не восстановить.

### 4.5. Сквозной гейт роняли собственные правки

04.09 гейт был красным несколько раз подряд (03.09 он был зелёным). Причины
разные, но показательные: устаревший сгенерированный клиент после правок
OpenAPI; сервис в compose, собранный из пакета, намеренно исключённого из
workspace; тест, который кликал в центр карточки и проходил случайно, потому что
имя объекта было длинным. Последнее стоит запомнить: **тест, проходящий по
случайному стечению вёрстки, хуже отсутствующего.**

### 4.6. ERP-фронтенд по-прежнему вне гейтов

`apps/erp-web` под версионированием, но исключён из pnpm-workspace, а его сервис
убран из compose: образ собрать нельзя, пакета в lockfile нет. Позицию бэклога
TEAM-001 подтвердить нечем.
