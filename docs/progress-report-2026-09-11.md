  репозиторий без этих ключей вовсе. Добавлен тест на реальный сценарий.

## 5. Поправки к прежним утверждениям

- **P1-05 «принят в браузере» (07.09).** Основанием был интеграционный тест на
  уровне сервисов, минуя HTTP. Браузерная спека прошла впервые 10.09, после
  исправления самой спеки и бага `listForBuilding`.
- **P1-06 «подборки на сервере» (07.09).** Это верно для CRM-подборок агента.
  Подборки покупателя на витрине серверного backend не имеют.
- **«lint 21/21» (07–09.09)** не включал `erp-web`: 1269 ошибок eslint, почти все
  унаследованные.
- **«production-grade» (10.09)** для messenger неверно, для LMS и community — до
  исправлений 10.09 неверно, после — с оговорками из раздела 4.

## 6. Оценка готовности

Пересчёт по этапам не делался. На 07.09 оценка была 40–50%. С тех пор этапы
9–11 появились в коде частично, поэтому та цифра занижена. Обследование 10.09
для плана переезда (вне репозитория) даёт экспертный диапазон 55–65%. Эта сверка
цифру не меняет: исправления 10.09 закрывают дефекты, а не добавляют объём.

## 7. Процесс

- **Параллельные сессии в одном рабочем дереве.** 11.09 в дереве лежали чужие
  незакоммиченные правки identity и схем, пока шла другая работа. §12.3
  мастер-плана требует, чтобы модуль или набор файлов на время задачи
  принадлежал одному агенту. Перед пушем проверять
  `git log origin/codex/integration..HEAD`: коммиты другой сессии не должны
  уезжать без её ревью.
- **Бюджет CI.** Каждый пуш запускает три workflow, runtime-гейт идёт 13–24
  минуты. На приватном репозитории бесплатные минуты кончились 10.09. Выбор
  между публичным репозиторием и своим раннером — за владельцем.
- **Пуш поверх красного гейта** не должен повторяться: следующий коммит
  маскирует причину падения предыдущего.
