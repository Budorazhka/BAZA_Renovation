# Задача: marketplace UI по Figma — извлечение, гейт, первая волна

Дата постановки: 04.09.2026. Исполнитель: Codex.

## Зачем эта задача существует

ТЗ §5.1 запрещает сдавать marketplace в виде generic-интерфейса и требует, чтобы
каждый UI-пакет изменений имел запись в `docs/discovery/figma-ui-delivery-gate.md`
с точными node ID, desktop/mobile-вариантами и результатом visual compare.

Сейчас гейт пройти невозможно, и не из-за нехватки времени. Обследование Figma от
25.08.2026 велось через `GET /v1/files/:key?depth=3` — API отдал дерево только до
уровня «страница → секция → фрейм верхнего уровня». Поэтому:

- известно **13 node ID, и все они секционные**; ни одного ID конкретного экрана;
- `docs/discovery/marketplace-screen-build-spec.md` §3 содержит 27 экранов
  (`MKT-SCR-001`…`MKT-SCR-027`), и почти в каждом на месте точного ID стоит
  `[Требуется ручное извлечение из Figma]`;
- `/v1/files/:key/styles` вернул **403** — реальные значения цветов и
  типографики не выгружены вообще, а раздел 5 инвентаря собран со скриншота
  панели стилей;
- варианты внутри `COMPONENT_SET` (hover/focus/disabled) не разворачивались ни
  разу — известен только факт, что варианты есть.

Задача закрывает этот разрыв: сначала механическое извлечение, потом решения
владельца, и только потом код.

## Вход, без которого задача не начинается

**Нужен временный Figma personal access token владельца** со scope, покрывающим
и содержимое файла, и стили:

- `file_content:read` — дерево узлов на полную глубину;
- `file_metadata:read` — `lastModified`, проверка актуальности;
- scope, дающий доступ к `GET /v1/files/:key/styles` (в прошлый раз его не
  запросили, и запрос вернул 403 — повторить эту ошибку нельзя, без стилей
  задача теряет половину смысла).

Файл: `https://www.figma.com/design/VEhjCW3yruV1B04Xy8VC4M/Batumi-Real-Estate-Project`,
file key `VEhjCW3yruV1B04Xy8VC4M`.

Токен **не коммитить, не писать в код, не оставлять в истории команд**: передать
через переменную окружения на время прогона и попросить владельца отозвать его
после. Прошлое обследование это правило соблюдало, нарушать его не начинаем.

**Отдельно, чтобы не потратить день впустую:** файл `figma_initial.json` в корне
рабочей папки **не является выгрузкой Figma**. Проверено 04.09.2026 — его верхние
ключи `INITIAL_OPTIONS`, `EARLY_ARGS`, `Fig`, это bootstrap-payload браузера, а не
дерево документа. Извлечь из него node ID нельзя.

## Не-цели

- Не трогать backend, OpenAPI, worker, авторизацию и persistence.
- Не тащить вёрстку, цвета и структуру со старого сайта `baza.sale`. Он
  допустим только как инвентарь функций и SEO.
- Не реализовывать разделы Figma вне scope marketplace (CRM риэлтора, рейтинг
  риэлторов, запросы) без отдельного решения владельца.
- Не выдумывать дизайн-систему, палитру, hero-блоки, иллюстрации и фильтры.
- Не пушить. Коммиты — локально, push только по отдельной явной команде.

## Этап 1. Извлечение (механическое, без дизайнерских решений)

Никаких оценочных суждений на этом этапе: только то, что реально лежит в файле.

**1.1. Проверить актуальность файла первым делом.** На 25.08.2026
`lastModified` был `2026-03-13`, то есть макет не редактировался 5,5 месяцев.
Если дата изменилась — весь инвентарь от 25.08 считается потенциально
устаревшим, и об этом сообщается до начала работы, а не после.

**1.2. Полный обход дерева.** Три canvas: `0:1` (Main pages, 11 секций,
436 фреймов на глубине 3), `40:4517` (UI kit), `40:4546` (Рабочий процесс).
Результат — машинно-сгенерированный реестр узлов, коммитится как артефакт:

```
docs/discovery/figma-node-registry.json
```

По каждому узлу: `id`, `name`, `type`, `absoluteBoundingBox` (ширина/высота —
по ним отличается desktop 1920 от mobile 375), путь родителей, canvas.

**1.3. Закрыть placeholder-ы в build-spec.** Каждое
`[Требуется ручное извлечение из Figma]` в §3
`marketplace-screen-build-spec.md` заменить на точный node ID. Там, где фрейма
физически нет, писать не ID, а `Figma gap` с указанием, чего именно нет.

**1.4. Выгрузить стили и превратить в токены.** `GET /v1/files/:key/styles` плюс
значения из узлов: реальные HEX по именованным color styles (`Main color`,
`dart text`, `light grey`, `light element background`, `element stroke`,
`back gradient`, `subheader gradient`, `Error bg`, `Error`, `hover green`) и
реальные размеры/интерлиньяж по текстовым стилям (`Comf 20/18/16/14/12`,
`Jak 28/24/20/18`), включая **настоящие font-family** — `Comf` и `Jak` это
внутренние алиасы дизайнера, а не названия шрифтов.

Результат ложится в `apps/marketplace-web/src/styles/tokens.css`. Файл сейчас 45
строк, и его шапка утверждает, что цвета взяты из UI kit `40:4532`. Цвета,
вероятно, честные. А вот шкала отступов (`--space-1: 4px` … `--space-20: 80px`),
шкала текста (`--text-xs: 0.75rem` …), `--radius-pill: 999px` и
`--text-display: clamp(2.25rem, 4.5vw, 3.75rem)` выглядят как обычная типовая
шкала, а не как значения из макета с фиксированной шириной 1920. **Каждый токен
должен получить либо подтверждение из Figma, либо пометку, что он придуман.**
Придуманные значения в файле, который называется токенами Figma, — это ровно то,
что гейт запрещает.

**1.5. Развернуть COMPONENT_SET.** По ключевым интерактивным компонентам
(`head menu`, `small button with icon`, `кнопки управления объектом`,
`актуальность`, `статус`, карточки объектов `card ЖК`, `card квартира в
новостройке`, `card квартира вторичка`, `card Проект`, `card дом`,
`card участок`, `card коммерция`, `Квартира аренда`, `filter`) выписать реальные
имена вариантов. Это единственный способ узнать, какие состояния нарисованы:
hover, focus, disabled, active — или их нет и это gap.

**1.6. Собрать конфликты в список.** Не решать их, а перечислить: 4 версии
фрейма `Home page` в `1035:18100`, `footer 1`–`footer 5` в `3067:73633`, две
версии `Рейтинг риелторов` в `3576:56354`, два фрейма с пометкой
`(не используется)` — `ЖК целая страница` и `Проект целая страница` в
`3314:195935`.

## Этап 2. Гейт и решения владельца

**2.1. Свести решения в один список.** Сейчас они разбросаны: 5 пунктов в
`marketplace-screen-build-spec.md` §10 и 4 в разделе «Открытый запрос владельцу»
в `figma-ui-delivery-gate.md`. Владельцу уходит **один** документ, а не два, и в
нём против каждого пункта стоит конкретный node ID из этапа 1, чтобы решение
принималось по ссылке на фрейм, а не по описанию словами.

**2.2. Заполнить реестр реализации в гейте.** По каждому экрану первой волны:
route, Figma URL + node ID, desktop/mobile, целевые файлы, подтверждённые
states, Figma/API gap, статус. До visual compare статус экрана — `scaffold`, и
никак иначе.

**2.3. Отдельным списком — backend gaps.** Если данных API не хватает для
Figma-блока, это фиксируется как gap, а не маскируется placeholder-данными и не
приводит к молчаливому упрощению дизайна.

## Этап 3. Реализация первой волны

**Начинается только после ответов владельца по этапу 2.** Порядок волн — тоже
его решение; кандидаты по инвентарю: каталог (список и карта), детальная
карточка объекта, попап быстрого просмотра, фильтры.

Целевое приложение — `apps/marketplace-web`, текущие маршруты:

| Route | Компонент |
| --- | --- |
| `/` | `CataloguePage` |
| `/developments/:slug` | `DevelopmentDetailPage` |
| `/listings/:slug` | `ListingDetailPage` |
| `/publish` | `PublishingWizardPage` |

Реестр гейта помечает текущий scaffold как
`BLOCKED — rewrite from exact Figma frames`. Это **переписывание с точных
фреймов, а не доводка отступов**. Существующие `figma-surface.css` (703 строки) и
`app.css` (1987 строк) писались до появления точных ID и подлежат ревизии, а не
сохранению по умолчанию.

Правила работы:

- один экран — один коммит, и в том же коммите запись в реестре гейта;
- брекпоинта ровно два: desktop 1920 и mobile 375. Промежуточного tablet в
  файле нет ни в одном фрейме — не придумывать его;
- размеры, сетка, отступы, типографика, цвета, радиусы, границы и состояния
  снимаются из Figma, а не подбираются на глаз;
- реальные loading/empty/error состояния не заменяются красивой картинкой и не
  выкидываются ради совпадения с макетом.

## Жёсткие запреты

Из ТЗ §5.1 и гейта. Нарушение любого пункта — повод вернуть работу целиком, а не
поправить деталь.

- Придуманная дизайн-система, палитра, типографика, структура карточек,
  hero-блоки, placeholder-иллюстрации, копирайт, фильтры.
- Перенос HTML/CSS/визуального паттерна со старого `baza.sale`.
- Generic design skills и «красивые» шаблоны как замена Figma. Они допустимы
  только для технической реализации уже подтверждённого решения и не могут
  менять композицию.
- Фейковые метрики, fake stock imagery, несуществующие фильтры.
- Угадывание при выборе между вариантами фрейма или при пометке
  `(не используется)`.
- Изменение дизайна под ограничение API вместо фиксации backend gap.

Отдельно: общие фронтенд-правила исполнителя (любые личные анти-слоп чек-листы,
дефолтные шкалы, привычные токены) **уступают Figma этого проекта**. Здесь
источник визуальной правды один, и он не в голове исполнителя.

## Definition of Done

Этапы 1–2 считаются сделанными, когда:

- [x] `docs/discovery/figma-node-registry.json` закоммичен и воспроизводим;
- [x] в `marketplace-screen-build-spec.md` §3 не осталось
      `[Требуется ручное извлечение]` — либо точный ID, либо явный `Figma gap`;
- [x] `tokens.css` содержит значения из Figma, а каждый не подтверждённый токен
      помечен как придуманный;
- [x] варианты COMPONENT_SET выписаны, состояния известны поимённо;
- [x] владельцу ушёл один сводный список решений с node ID против каждого;
- [x] `pnpm typecheck` и тесты зелёные.

Этап 3 — по чек-листу «Definition of Done для marketplace UI» в
`figma-ui-delivery-gate.md`, без сокращений.

## Формат отчёта

Не «сделал страницу», а ровно пять пунктов (§«Формат отчёта исполнителя» гейта):

1. Figma refs: URL и node ID.
2. Реализованные файлы.
3. Что совпало с Figma.
4. Каких states в Figma нет и как они согласованы.
5. Пути скриншотов и результат visual compare.

## Что известно про сроки и риски

- **Задача упирается в человека дважды**: токен на входе и решения на этапе 2.
  Оба ожидания стоит запускать раньше, чем закончится предыдущий этап.
- **Макет может быть устаревшим.** Пять с половиной месяцев без правок при
  живом продукте — это не признак стабильности, а повод спросить владельца,
  актуален ли файл вообще, до того как по нему сверстают 27 экранов.
- **Оценки готовности marketplace в процентах к этому гейту отношения не
  имеют.** Поиск, карта и форма раскрытия контакта работают — по гейту это
  ноль сделанных экранов. Смешивать две шкалы на приёмке нельзя.
