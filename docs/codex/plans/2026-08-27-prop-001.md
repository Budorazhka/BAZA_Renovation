# PROP-001 PropertyAsset + sale/rent Listings

## Goal

Deliver the first backend vertical slice for secondary/rent property: one tenant-scoped `PropertyAsset` may have independent sale and rent `Listing` offers.

## Non-goals

- Marketplace UI, Figma implementation, map/search, duplicate detection, actuality jobs, publication projection, bookings, billing, or legacy import.
- Marketplace-account (non-ERP) authoring; this slice starts with authenticated organization scope.

## Tasks

- [x] Add canonical Mongoose schemas for `PropertyAsset` and `Listing` with explicit organization publisher scope, GeoJSON location, MoneyAmount, deal type and lifecycle fields.
- [x] Add tenant-filtered repositories and service commands for asset creation/read and sale/rent listing creation/read.
- [x] Add ERP HTTP endpoints under `/api/v1/property-assets` and `/api/v1/property-assets/:assetId/listings` with DTO whitelist validation and permission guards.
- [x] Enforce invariants: parent asset belongs to current organization; only one active listing per deal type; sale and rent may coexist; client cannot submit organizationId/publisherScope.
- [x] Add default grants for the new commands and unit/integration regression coverage for tenant escape and sale+rent coexistence.
- [x] Update API evidence after implementation and verification.

## Verification

- Focused repository/service/controller tests.
- API typecheck and full unit suite.
- Integration tests against MongoDB replica set, including cross-organization 404 and duplicate active deal-type conflict.

## Risks

- Keep publication and duplicate workflows out of this slice so no legacy marketplace behavior is reintroduced.
- Use existing transaction, tenant, audit and error patterns; do not introduce a second repository or auth model.
