# Спецификация API для CRM «Воронка» (Poker Table)

**Status:** Approved
**Version:** 1.2
**Base URL:** `/api/development` (or relative to the configured base endpoint)
**Auth:** Bearer Token required for all endpoints

**Base URL:** `https://api-crm.baza.sale` (или локальный сервер из `.env`)

---

## 1. Настройки распределения лидов

Фронтенд уже обращается к этим эндпоинтам. Пока они не реализованы (возвращают 404/501), данные сохраняются в `localStorage`.

### GET `/crm/settings/distribution`
Получение текущего режима распределения лидов.
**Ответ:**
```json
{
  "success": true,
  "data": {
    "type": "round_robin", // варианты: "round_robin", "by_load", "manual"
    "manualDistributorId": "692614a013536c56a359f9cf" // или null
  }
}
```

### POST `/crm/settings/distribution`
Сохранение настроек распределения.
**Тело запроса:** (аналогично объекту `data` из GET)
**Ответ:** `ApiResponse<DistributionSettings>`

---

## 2. Массовые действия с лидами

### POST `/crm/leads/bulk-assign`
Массовая передача всех лидов от одного менеджера другому.
**Тело запроса:**
```json
{
  "fromManagerId": "uuid-1",
  "toManagerId": "uuid-2"
}
```
**Логика:** Все лиды, где `assignedTo == fromManagerId`, должны сменить владельца на `toManagerId`.

---

## 3. Оптимизация списка лидов

### GET `/crm/leads`
В текущий объект лида необходимо добавить два вычисляемых поля, чтобы избежать лишних запросов за задачами:
*   `hasTask`: `boolean` — есть ли хоть одна невыполненная задача.
*   `taskOverdue`: `boolean` — есть ли просроченная невыполненная задача.

---

## 4. Создание задач

### POST `/tasks`
Фронтенд отправляет запрос при создании задачи из таймлайна лида.
**Тело запроса:**
```json
{
  "title": "Связаться с клиентом",
  "leadId": "692614a013536c56a359f9cf",
  "endDate": "2026-06-20T12:00:00Z",
  "priority": "high", // или "normal"
  "description": "Создано из воронки..."
}
```

---

## 5. Real-time события (WebSockets)

Сервер должен транслировать события через **Socket.io** (канал `SOCKET_ORIGIN`) при изменении данных в БД, чтобы воронка обновлялась мгновенно у всех пользователей.

### Требуемые события:
1.  `lead:updated` — данные: полный объект лида. Отправлять при смене стадии, менеджера или полей лида.
2.  `lead:created` — данные: полный объект нового лида.
3.  `task:created` / `task:updated` — данные: объект задачи. При получении этих событий воронка инициирует полный переприем списка лидов для обновления индикаторов задач.

---

## 6. История изменений (Timeline)

### GET `/crm/leads/:id`
Массив `history` внутри лида должен содержать объекты со следующей структурой для корректного маппинга:
```json
{
  "changedAt": "2026-06-13T10:00:00Z",
  "changedBy": "user-uuid",
  "userName": "Иван Менеджеров",
  "type": "stage_change", // или "assign", "comment"
  "fromStage": "needs_analysis",
  "toStage": "presentation",
  "comment": "Клиент готов к зуму"
}
```

---

### Текущий статус на фронтенде:
Код полностью готов. Если бэкенд возвращает ошибку на новые эндпоинты, фронтенд бесшовно переходит на **локальные заглушки** (LocalStorage / расчеты в памяти), поэтому работа пользователей не прерывается.
