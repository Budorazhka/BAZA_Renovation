# Спецификация для фронта: Раздел «История AI» в чатах

> Дата: 2026-07-01
> Статус: бэкенд реализован, фронт к реализации

---

## 1. Обзор

В диалоге (чате) с клиентом добавляется новый раздел **«История AI»**, расположенный между разделами «AI» и «Материалы». Раздел показывает ежедневную сводку всех действий ИИ-риелтора с лидом в CRM.

---

## 2. Навигация (табы/разделы в чате)

Порядок разделов в интерфейсе чата:

1. **AI** — текущий чат с клиентом (сообщения)
2. **История AI** — ежедневные сводки действий ИИ (НОВЫЙ)
3. **Материалы** — файлы и документы

---

## 3. Внешний вид раздела «История AI»

### 3.1. Список дней (аккордеон)

Дни отображаются **сверху вниз** от самого нового к старому.

Каждый день — это кнопка-аккордеон:

```
┌──────────────────────────────────────┐
│  ПН, 29.06.2026                🔵    │  ← непрочитанный (синяя точка)
├──────────────────────────────────────┤
│  ВТ, 28.06.2026                      │  ← прочитанный
├──────────────────────────────────────┤
│  СР, 27.06.2026                🔵    │  ← непрочитанный
└──────────────────────────────────────┘
```

- Формат названия кнопки: `ДД, ДД.ММ.ГГГГ` (день недели, число.месяц.год)
- Непрочитанные дни отмечаются **индикатором** (точка/бэйдж) справа от даты
- При нажатии кнопка раскрывается и показывает сводку за день

### 3.2. Раскрытая сводка за день

При клике на кнопку дня она раскрывается и показывает 4 блока:

## 4. API эндпоинты

### 4.1. Получение истории

**GET** `/api/dialogs/{dialogId}/ai-history`

**Параметры запроса:**
| Параметр | Тип | Описание |
|----------|-----|----------|
| limit | integer | Количество дней (по умолчанию 30) |
| offset | integer | Смещение (для пагинации) |

**Ответ 200:**
```json
{
  "success": true,
  "history": [
    {
      "_id": "abc123",
      "dialogId": "dialog_id",
      "userId": "user_id",
      "date": "2026-06-29T00:00:00.000Z",
      "summary": {
        "whatHappened": "AI ответил клиенту на 3 сообщения, обновил описание лида в CRM, переместил лид с needs_analysis на presentation.",
        "clientMessages": "Клиент спрашивал о availability квартир в Батуми, интересовался ценами на 2-комнатные квартиры, уточнял возможность ипотеки.",
        "aiReplies": "AI предоставил информацию о доступных квартирах, предложил варианты в районе Батуми, ответил на вопрос об ипотеке.",
        "updatedData": "Добавил Город: Батуми. Изменил Бюджет на 80000."
      },
      "readBy": ["user_id_1"],
      "createdAt": "2026-06-29T15:30:00.000Z",
      "updatedAt": "2026-06-29T18:45:00.000Z"
    }
  ],
  "unreadCount": 2
}
```

### 4.2. Отметить день как прочитанный

**POST** `/api/dialogs/{dialogId}/ai-history/read`

**Тело запроса:**
```json
{
  "date": "2026-06-29T00:00:00.000Z"
}
```

> Если `date` не передан — помечаются **все** непрочитанные дни.

**Ответ 200:**
```json
{
  "success": true
}
```

### 4.3. Отметить всю историю как прочитанную

**POST** `/api/dialogs/{dialogId}/ai-history/read-all`

**Ответ 200:**
```json
{
  "success": true
}
```

### 4.4. Получить количество непрочитанных

**GET** `/api/dialogs/{dialogId}/ai-history/unread-count`

**Ответ 200:**
```json
{
  "success": true,
  "unreadCount": 3
}
```

## 5. Логика прочтения

### Когда день считается непрочитанным:

1. **Новый день** — ИИ записал новую сводку за день (создана запись). Если риелтор не открыл этот день — он непрочитанный.

2. **Обновление существующего дня** — ИИ дописал/обновил сводку за текущий день (новые действия в CRM). Если риелтор уже видел предыдущую версию, но были изменения — день снова становится непрочитанным (`readBy` очищается).

### Когда день считается прочитанным:

1. Риелтор **открыл раздел «История AI»** → все видимые дни помечаются как прочитанные.
2. Риелтор **нажал на конкретный день** → этот день помечается как прочитанный.
3. Риелтор нажал **«Отметить все как прочитанные»** → все дни помечаются прочитанными.

## 6. WebSocket события

### ai:history_updated

Отправляется при обновлении истории (новая сводка или обновление существующей).

```typescript
{
  dialogId: string;
  date: string; // ISO date
  unreadCount: number;
}
```

**Что делает фронт:**
- Обновляет список дней в разделе «История AI»
- Обновляет индикатор непрочитанных (точка/бэйдж на кнопке раздела)

## 7. TypeScript интерфейсы

### messengerApi.ts

```typescript
export interface AiHistorySummary {
  whatHappened: string;
  clientMessages: string;
  aiReplies: string;
  updatedData: string;
}

export interface AiHistoryEntry {
  _id: string;
  dialogId: string;
  userId: string;
  date: string;
  summary: AiHistorySummary;
  readBy: string[];
  createdAt: string;
  updatedAt: string;
}

export interface AiHistoryResponse {
  success: boolean;
  history: AiHistoryEntry[];
  unreadCount: number;
}
```

### messengerApi.ts — методы

```typescript
getAiHistory: async (dialogId: string, limit?: number, offset?: number): Promise<AiHistoryResponse> => {
  const params = new URLSearchParams();
  if (limit) params.set('limit', String(limit));
  if (offset) params.set('offset', String(offset));
  const query = params.toString();
  const response = await api.get(`/dialogs/${dialogId}/ai-history${query ? `?${query}` : ''}`);
  return response.data;
},

markAiHistoryRead: async (dialogId: string, date?: string): Promise<void> => {
  await api.post(`/dialogs/${dialogId}/ai-history/read`, { date });
},

markAllAiHistoryRead: async (dialogId: string): Promise<void> => {
  await api.post(`/dialogs/${dialogId}/ai-history/read-all`);
},

getAiHistoryUnreadCount: async (dialogId: string): Promise<number> => {
  const response = await api.get(`/dialogs/${dialogId}/ai-history/unread-count`);
  return response.data.unreadCount;
},
```
